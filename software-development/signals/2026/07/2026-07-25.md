### 信号

SyncPetri 预印本把并发 Rust API 的资源、生命周期、因果依赖与冲突表示为 Colored Petri Net，再生成含事件、偏序、可接受结果类和不可改写约束的 ScenarioBlueprint（场景蓝图），由 LLM 只负责将其具体化为 Rust 测试。生成后先通过编译、marker（事件标记）覆盖与局部忠实合同，再以结构、结果、不变量和活性四层 oracle（判定器）区分“生成测试失真”与“被测 API 可能失效”；Petri 模型还据冲突对选择带 barrier/yield 的 Loom 兼容 macro harness（宏观并发测试框架），在其中探索 micro-interleaving（微观交错）。

### 为什么重要

该方法不把语义正确性交给 LLM 自行推断，而将模型负责的资源协议与 LLM 负责的代码实现分开。对有句柄、许可证、关闭状态和并发交错的 API，这种边界可避免测试虽能编译却跳过深状态、弱化断言或把竞态序列化。

### 尚待确认

- 当前评估仅有一个容量为一的 Tokio MPSC 场景、两个合法调度、三次运行和一个修复后的生成测试；代码与评测 harness 未公开，推理或调度预算未披露，也没有基线指标或统计比较，不能证明可复跑性、统计优势或缺陷发现能力。
- Petri 网、adapter、场景不变量和 API 专用 oracle 需要人工编写；其建模成本、错误率和跨库迁移性尚未量化。
- 尚无纯 prompt、现有 fuzzing/模型测试或大规模 mutant corpus 的对照，也未公开长时调度预算和多模型重复结果。
