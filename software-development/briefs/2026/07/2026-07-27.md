#### 核心判断

Simon Willison 转述的调查显示，部分低价 LLM 中转服务会聚合不同来源的模型额度，并通过 OpenAI-compatible gateway 向开发者转售。对使用 coding agent 的团队而言，这首先是一个供应链信任问题：便宜的推理价格可能同时隐藏凭证合规、模型替换、请求留存和失控账单风险。

#### 变化与技术机制

中转层把多个上游账号或额度池包装成统一 API，调用方看到的是熟悉的模型名、端点和计费单位，却无法从接口本身验证额度来源、实际路由模型或数据保留方式。调查转述还指出，滥用试用额度、未设支出上限的公开支持机器人、盗刷或拒付都可能成为低价供给来源；一旦中转方发生封禁、换模或余额归零，依赖它的 coding agent 会在任务执行中直接失去能力。工程控制因此需要从“密钥有没有泄露”扩展到上游授权、模型身份、配额隔离、并发限制和异常成本检测。

#### 关键解读

##### API 兼容只解决接入，不证明供应链可信

OpenAI-compatible 接口降低了切换成本，也让不透明中转更容易伪装成普通供应商。团队需要把模型身份、上游授权和数据处理承诺作为独立验收项，不能用“SDK 能正常返回结果”替代供应链验证。

##### 成本护栏必须在上游和应用侧同时存在

单靠供应商侧余额不足以控制风险；公开端点、支持机器人和自动化代理还需要按租户设置硬支出上限、并发上限和异常斜率告警。这样即使凭证被转卖或工作负载被放大，损失也不会无限扩张。
